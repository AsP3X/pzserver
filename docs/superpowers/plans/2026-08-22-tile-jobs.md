# Tile Jobs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a tile job the only way to refresh part of the isometric pack — world squares in, dirty DZI tiles internally, in-place WAL replace, map stays up — with CLI and a small admin API sharing one runner.

**Architecture:** Planner turns squares/cells into dirty tiles, merge siblings, and covering cells. The existing `map-tiles` container unpacks siblings, paints those cells, packs only dirty keys into the live `tiles.sqlite`. web-api stays up (volume writable for WAL shm). POST `/api/v1/admin/map-tiles/rerender` returns 202 and starts that container through the Docker socket proxy.

**Tech Stack:** Python (planner/packer/run.sh, pytest), SQLite WAL, Axum + sqlx, Docker Engine API via existing socket proxy, Compose.

**Spec:** `docs/superpowers/specs/2026-08-22-tile-jobs-design.md`

---

## Read this first — the rules

Do not “improve” past these. They are how black holes and a downed site happened.

- Expand to **whole tiles** before `render_cell_range`.
- Dirty **every packed ancestor**, not only level 20.
- Restore **siblings**, never dirty tiles.
- Pack **only dirty keys**. No VACUUM on a region. No rename of `tiles.sqlite`.
- Do not stop `web-api`. Do not treat a region as a first render.
- HTTP does not wait for the render (`202` + job id).
- `omit_levels` pin (`patch_scheduler.py`) and `check_cache.py` stay.

Spec said POST invalid input → 400. This API already maps `ApiError::Validation` to **422**. Use that. Conflict stays **409**.

```python
def square_rect_to_tiles(geo: Geometry, rects, levels) -> set:
    """Every `(level, x, y)` tile touched by any world-square rect."""
    tiles = set()
    for x, y, w, h in rects:
        lo_x, lo_y, hi_x, hi_y = geo.square_rect_bounds(x, y, w, h)
        for level in levels:
            span = geo.span(level)
            for tx in range(int(lo_x // span), int(hi_x // span) + 1):
                for ty in range(int(lo_y // span), int(hi_y // span) + 1):
                    if tx >= 0 and ty >= 0:
                        tiles.add((level, tx, ty))
    return tiles
```

```python
def dirty_pyramid(leaves: set, max_level: int, min_level: int) -> set:
    """Leaves at max_level plus every parent down to min_level."""
    dirty = set()
    for z, x, y in leaves:
        cz, cx, cy = z, x, y
        while cz >= min_level:
            dirty.add((cz, cx, cy))
            cz -= 1
            cx >>= 1
            cy >>= 1
    return dirty
```

- [ ] **Step 3: Service**

`map_tile_jobs.rs`:

- `Rect = [i32; 4]` via serde as JSON arrays
- `Enqueue { squares: Vec<[i32; 4]>, cells: Vec<[i32; 4]> }`
- `Job { id, squares, cells, status, error, tiles_replaced, created_at, ... }`
- `enqueue(state, body) -> ApiResult<Job>`:
  - if both squares and cells empty → `Validation("provide squares or cells")`
  - each rect length 2 (promote to w,h=1) or 4; reject other lengths
  - `inspect` Docker `pz-map-tiles` — if 200 → `Conflict { field: "job", message: "a map tile job is already running" }`
  - INSERT status `queued`, then `tokio::spawn` `run_job`
  - return job (`queued`)
- `get(db, id) -> ApiResult<Job>` — none → `NotFound`
- `run_job`: UPDATE `running`; `POST {proxy}/containers/create?name=pz-map-tiles` with body:

```json
{
  "Image": "<map_tiles_image>",
  "Env": ["PZ_MAP_SQUARES=x,y,w,h;...", "PZ_MAP_CELLS=...", "PZ_GAME_VERSION=..."],
  "HostConfig": {
    "Binds": [
      "<pz_server_host>:/pz:ro",
      "<pz_texturepacks_host>:/pz/media/texturepacks:ro",
      "<map_tiles_host>:/out"
    ],
    "ShmSize": 25769803776,
    "AutoRemove": true
  }
}
```

Then `POST .../containers/pz-map-tiles/start`. Wait: `POST .../containers/pz-map-tiles/wait` with a **long** reqwest client (1 hour). On exit 0: `done`.
